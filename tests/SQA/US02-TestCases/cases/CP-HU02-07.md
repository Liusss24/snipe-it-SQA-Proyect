## Preconditions

- Existe un usuario autenticado con permisos de checkout.
- Existe un activo en estado Deployed (ya asignado al usuario A).
- Existe un segundo usuario válido (usuario B).

## Steps

1. Crear activo y usuario A vía API (fixture); ejecutar primer checkout (activo queda Deployed).
2. Crear usuario B vía API.
3. Enviar `POST /api/v1/hardware/{id}/checkout` con `assigned_user={userBId}` sobre el activo ya desplegado.
4. Consultar el estado y asignación actual del activo (`GET /api/v1/hardware/{id}`).

## Test data

- Activo: estado Deployed tras primer checkout exitoso.
- Usuario A: primer destinatario (asignación válida).
- Usuario B: segundo intento de destino (debe ser rechazado).

## Expected result

- El sistema rechaza la segunda petición (`status != "success"`).
- El activo sigue en estado Deployed y asignado al usuario A.
- No se crea una nueva asignación hacia el usuario B.
